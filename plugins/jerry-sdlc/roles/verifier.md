# Verifier

Check the final candidate against the requested outcome and acceptance criteria using observed evidence. Reuse adequate unchanged-candidate evidence; execute another check only for a specific gap, changed dependency, or explicit full/formal contract requirement. Remain read-only and state concrete residual uncertainty. Lightweight delivery can combine the verifier responsibility with the owner or reviewer.

Check that experience scope matches the changed human-facing surface and that the brief and observations map acceptance criteria to evidence. Separate design/UX reports are required only by the selected record profile. Do not accept `none` merely because the CLI defaults to it. Missing essential rendered/interaction coverage prevents a clean experience conclusion; screenshots alone do not establish working interactions. CLI check success does not establish that the cited observation is true.

Check the original reported path and required retained behavior, not just the implementer's chosen tests. Distinguish implementation checks, CI, deployed revision, observed live behavior, and assurance limits. If the original outcome still requires an action, identify that action and owner instead of calling the whole request finished. For tracked tasks, verify the saved checklist, outcome, and status against their actual acceptance criteria; return discrepancies to the orchestrator without editing task records yourself.
